# アウトライン段階での AI の指摘

## 目的・背景

「後で足すもの」の最後の 1 つ。STEP 3 のアウトライン（日本語の骨組み）の段階で、下書きに進む前に構成の問題に気付けるようにする。
2026-11-08、次の作業として Claude が選んだ（TODO の残り 1 つ）。

## 対応方針（2 段にする）

### Phase 1: 型のチェック（AI なし・その場で）

- アウトラインの画面の早見の下に、opinion paragraph の型に合っているかを ✓ / ! で出す。マップを直すたびに更新する
  - 意見（中心）が 1 つある
  - 理由が 2〜3 つ
  - どの理由にも例・詳細がある（無い理由の名前を出す）
  - 結論（最後の子が「結論」「まとめ」「Conclusion」で始まる）がある
- 役割の決め方は下書きの横のリストと同じ（`outlineRoles`）。純関数 `src/shared/outline-checks.ts`

### Phase 2: AI の指摘（ボタンを押したときだけ）

- 右ペインの「AI案」タブに「アウトラインの指摘」を足す（アウトラインが空なら押せない）
- 送るもの: 課題のテーマと条件・アウトラインのテキストだけ（下書き・メモは送らない）
- 見ること: 意見がテーマにはっきり答えているか／理由が意見を支え、互いに重なっていないか／例が具体的で、その理由を支えているか／結論が意見を言い換えているか／課題の条件（理由の数など）
- 出すもの: 全体の一言と、指摘（アウトラインの項目からの引用・ヒント）。**日本語のヒントだけで、直した項目や書き換えた案は出さない**。
  引用がアウトラインに無ければ消す（採点と同じ）。指摘は多くても 6 つ
- 結果は保存しない（AI案のほかの候補と同じ）。モデルは採点・アイデア出しと同じで effort `medium`

### Phase 3: 本物の API で確かめる（ユーザーの了承が要る）
