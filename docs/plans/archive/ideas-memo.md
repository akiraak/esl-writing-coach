# アイデアのメモ

## 目的・背景

編集画面の STEP 2（アイデア）を作る。意見・理由・例を思いつくまま書き出す自由テキストで、日本語でよい（`CLAUDE.md` の「書く流れ」）。
保存先は `ideas.txt`。自動保存は編集画面の骨組みで作った仕組み（段階ごとの `StageEditor`）をそのまま使う。

モックにはアイデアの画面の詳細は無い（タイルの「7 行」だけ）。決まっているのは「自由テキスト」なので、入れ物は大きな複数行の欄 1 つにする。

## 対応方針（1 Phase）

- 中央のペイン: 上にテーマ（課題で入れたもの。空なら「課題でテーマを入れる」へのリンク）と課題の条件を小さく出し、その下に大きな複数行の欄
  - テーマ・条件は、手元の課題の内容（`assignment` の `StageEditor` の `text`）から読む。課題を直して移ってきたときも最新が出る
  - テーマと条件の帯は、下書きの画面（モックの `.req`）でも使うので部品に分ける（`src/browser/views/brief.ts`）
- 欄: 日本語の画面の文字（system-ui）、行間広め、高さは画面に合わせて大きめ（縦に伸ばせる）
  - 空のときの例（placeholder）: 意見・理由・例を書き出す例
  - 欄の下にヒント: 「順番や形は気にしない。ここで出したものを次のアウトラインで並べる」
- 打つたびに `editor.update(text)`。タイルの「N 行」は骨組みで対応済み
- 本文は加工しない（前後の空白も消さない。改行コード・BOM・末尾の改行は保存層が控えて戻す）

## 影響範囲

- 新規: `src/browser/views/ideas.ts`・`src/browser/views/brief.ts`
- `src/browser/views/edit.ts`（段階ごとの描き分けに足す）・`web/style.css`

## テスト方針

- 新しい純関数は無い。`npm test`・`npm run typecheck`・`npm run lint` が通ること
- 画面は 3017 番で立て、ヘッドレスブラウザで確かめる（試し用のパラグラフを作り、最後に消す）
  - 打つと 3 秒で `ideas.txt` に保存される・タイルの行数が変わる・段階を移って戻っても残る・再読み込みしても残る
  - 課題のテーマを直してからアイデアへ移ると、上のテーマが新しくなっている
