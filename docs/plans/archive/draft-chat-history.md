# 「AI に質問」で前のやりとりを会話として渡す

## 目的・背景

STEP 3 の「AI に質問」で続けて聞くと、前の質問と答えが AI に送られていないように見え、会話が不自然になる（2026-11-11 ユーザーの報告）。

調べたところ、前のやりとりは送られていた。ただし **1 つのメッセージの中に「それまでのやりとり」という資料として**、下書きの後ろに並べていたので、
AI は続きの会話としてではなく「下書きについての新しい質問」として読みやすかった。
実際の例: 2 回目で例の英文を出してもらい、3 回目に「その英文で良いかチェックして」と聞くと、直前の答えの英文ではなく下書き全体をチェックした。

## 対応方針

- 前のやりとりを **本物の会話（user / assistant の順のメッセージ）** として API に渡す（`src/ai/draft-chat.ts` の `buildDraftChatMessages`）
  - 最初の user のメッセージに、課題・アプリが数えた値・今の時点の下書きを付ける。そのあとに質問と答えを順に並べ、最後が今回の質問
  - assistant の過去の答えは、出力と同じ形（`{"answer": …}` の JSON）で入れる
- システムプロンプトに「続きの会話」と明記する: 「その英文」「それ」「さっきの」などは、まず直前のやりとり（とくに直前の答えで出した英文）を指すものとして読む。
  下書きは今の時点のもので、前の答えの英文がまだ入っていないことがある
- `src/ai/client.ts` の `callJson` に、メッセージの並びを渡せるようにする（ほかの AI は今までどおり 1 つのメッセージ）
- 送る中身（下書き・課題・語数と文数・それまでの質問と答え・今回の質問）は変わらない

AI案への質問（`src/ai/questions.ts`）も同じ「資料として並べる」形だが、今回は STEP 3 の「AI に質問」だけを直す。

## 影響範囲

`src/ai/draft-chat.ts`・`src/ai/client.ts`・`test/draft-chat.test.ts`・`CLAUDE.md`

## テスト方針

- `buildDraftChatMessages`: 役割が user / assistant の順に並ぶ・最初に課題と下書き・最後が今回の質問・やりとりが無ければ 1 つ
- 本物の API で、報告と同じ流れ（英文を出してもらう → 「その英文で良いかチェックして」）を確かめる
