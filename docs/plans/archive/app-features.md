# アプリの機能を決める

## 目的・背景

2026-11-07 にプロジェクトをゼロから作り直すことにし、コンセプトを「ESL の授業で書くパラグラフを、学びながら書くためのツール（自分専用・PC 専用）」と決めた。機能と画面構成はまだ何も決まっていない。実装と技術選定の前提になるので、先に機能を決めて文書にまとめる。

旧実装は「記事を書くと AI が添削とアドバイスを返す」汎用の英作文添削ツールだった。新しいコンセプトでは「パラグラフの書き方を**学ぶ**」ことに重心を置くため、旧機能はそのままでは引き継がず、必要なものだけ選び直す。

## 対応方針

ユーザーへのヒアリングで要件を集め、Claude が機能案にまとめ、ユーザーが確定する、という流れで進める。コードは書かない。

### Phase 1: ヒアリング

次の観点で、授業の実態と、ツールに期待することを確認する。

- **授業と課題**
  - 課題として書くパラグラフの種類（opinion / compare & contrast / process / cause & effect / narrative など）
  - 課題で与えられるもの（お題・ルーブリック・語数制限・締切・配布プリント）
  - 提出方法（Word / Google Docs / 手書き / LMS）と、ツールから持ち出す形式
  - 授業で教わる構成の型（topic sentence / supporting sentences / concluding sentence、transition words など）
- **学び方**
  - 「学ぶ」部分で欲しいもの（構成のガイド、パートごとのフィードバック、例文、チェックリスト、語彙・表現集など）
  - 書く流れ（アイデア出し → アウトライン → 下書き → 推敲、のどこを支援するか）
  - 日本語での下書きやメモを許すか
- **AI の関わり方**
  - AI に任せる範囲（構成への指摘・文法の添削・書き直し案の提示）
  - 課題として自力で書く必要がある前提で、AI がどこまで書き直してよいか（ヒントに留めるか、添削済み全文を出すか）
- **データ**（保存方式は daily-note と同じく Dropbox 上のファイルに決定済み。2026-11-08。詳細は `CLAUDE.md` の「データ保存」）
  - 課題やパラグラフを残すか、版の履歴を持つか
  - Dropbox 上の保存先フォルダ、ファイル形式（`.txt` / `.md` など）、ファイルの配置と命名
  - 課題文・下書き・AI のフィードバックを 1 ファイルにまとめるか、別ファイルに分けるか
  - daily-note と Dropbox アプリ（トークン）を共用するか、別に作るか
  - 旧 DB の記事（`/home/ubuntu/esl-writing-coach-backup-2026-11-07/` に退避済み）を Dropbox のファイルへ移行するか → 移さない
  - 旧実装で構想していた「課題プリントの画像を取り込む（OCR）」機能を入れるか

#### ヒアリング結果（2026-11-08〜）

- パラグラフの種類: **Opinion** のみ
- 支援する段階: **アイデア出し・アウトライン・下書き・推敲／添削の全部**
  - アウトラインは daily-note のマインドマップ機能（字下げテキストを木として図で見せる。正はテキストのまま）を使って作る
- AI の範囲: **指摘とヒントを出し、100 点満点で採点もする**（添削済みの全文は出さない）
- 採点基準: **アプリ内の固定基準**（opinion paragraph の一般的な基準。授業のルーブリックは入力しない）
- 日本語: **メモ（アイデア出し・アウトライン）だけ日本語可**。本文は英語のみ
- 課題で与えられるもの: **語数・文数の指定**、**構成や表現の条件**。配布プリントの取り込み（OCR）は不要
- お題: **自分で決める**。アイデア出しで AI がテーマ候補を出す
- 提出: **ファイルで提出**。`.docx` と PDF の**両方**を書き出せるようにする
- 学習用に見られるもの: **構成の解説・モデル文・表現集・間違いの振り返り**の全部
- 履歴: **最新だけ**（本文も採点結果も上書き）。間違いの振り返りは、各パラグラフの最新の指摘・点数を横断して集める形になる
- 旧 DB の記事: **移さない（全削除）**。新アプリは空から始める
- 動かす場所: **自分の PC だけ（ローカル・認証なし）**
- Dropbox の保存先: **daily-note の隣の専用フォルダ**（名前は Phase 3 で確定。案: `/akira/Documents/esl-writing/`）
- Dropbox アプリ: **daily-note と共用**（daily-note の `.env` の App key / App secret / リフレッシュトークンを使う）
- ファイル形式・配置、1 ファイルにまとめるか分けるかは Phase 2 で Claude が案を出す

### Phase 2: 機能案の作成

ヒアリング結果をもとに、Claude が機能一覧を作る。

- 各機能を **MVP（最初に作る）** と **後回し** に分ける
- 画面構成と画面遷移を簡単にまとめる（PC 専用のため、横幅を活かした複数ペインのレイアウトを前提にしてよい）
- 保存するデータの大まかな項目と、Dropbox 上のファイル配置を挙げる

#### 機能案（2026-11-08 作成。Phase 3 で一部変更して確定 → 下の「Phase 3 の決定」）

##### 基本の単位と書く流れ

1 つの課題につき **1 パラグラフ**を作る。パラグラフは次の 4 段階を順に進める。どの段階にもいつでも戻れる。

| 段階 | やること | 言語 | AI の関わり |
|---|---|---|---|
| 1. 課題 | テーマ（自分で決める）と、課題の条件（語数・文数の指定、構成や表現の条件）を入力する | 条件は英語でも日本語でも可 | テーマ候補を出す（任意） |
| 2. アイデア | 意見・理由・例を思いつくまま書き出すメモ | 日本語可 | 理由や例の候補を出す（任意） |
| 3. アウトライン | マインドマップで骨組みを作る。中心 = 意見（topic sentence の元）、子 = 理由、孫 = 例・詳細、最後に結論のノード | 日本語可 | なし（MVP） |
| 4. 下書き・推敲 | 英語で本文を書き、採点と指摘を受けて直す | **英語のみ** | 100 点満点の採点、指摘とヒント（直した全文は出さない） |

##### 機能一覧

**MVP（最初に作る）**

- **一覧画面**: パラグラフの一覧（テーマ・更新日・最新の点数）、新規作成、削除
- **課題の入力**: テーマ、語数・文数の指定、構成や表現の条件
- **アイデアのメモ**: 自由テキスト（日本語可）
- **AI のアイデア出し**: テーマ候補、理由・例の候補をボタンで出す。出た候補はメモに書き足せる（自動では書き込まない）
- **アウトライン（マインドマップ）**: daily-note のマップ機能を移植する。正は字下げのテキストで、図はその見え方（座標は保存しない）。移植元は `src/editor/outline.ts`・`src/editor/mindmap-layout.ts`・`src/browser/map.ts`
- **下書きエディタ**: 英語の本文。語数・文数を常に表示し、課題の指定と比べて足りない／超えたことが分かるようにする。アウトラインを横に並べて見ながら書ける（PC の横幅を使う）
- **AI の採点と指摘**: 「採点する」ボタンで実行する（自動では走らせない。料金と、書きかけで採点されるのを避けるため）
  - アプリ内の固定基準で 100 点満点を付け、観点ごとの内訳も出す（基準は下記）
  - 指摘は文や語句の位置に結び付け、観点ラベルとヒントを付ける。直した文そのものは出さない
  - 本文に日本語が混じっていれば、英語に直すよう指摘する
  - 結果は最新の 1 回分だけを持ち、採点し直すと上書きする
- **自動保存**: daily-note と同じく打ち終わって数秒で Dropbox に保存し、`rev` が合わなければ止めて知らせる
- **書き出し**: 下書きを `.docx` と PDF に書き出す
- **学習ガイド**: 書いている途中でも横に開ける
  - 構成の解説: opinion paragraph の型（topic sentence / reasons / examples / concluding sentence）
  - モデル文: 構成ごとに色分けしたお手本のパラグラフ（数本）
  - 表現集: 意見・理由・例・結論を述べる定型表現と transition words

**後回し**

- **間違いの振り返り**: 全パラグラフの最新の指摘・点数を観点別に集め、よくする間違いと点数の推移を見る。パラグラフがある程度たまってから作る
- アウトライン段階での AI の指摘（理由と例が意見を支えているか）
- 表現集から下書きへの挿入

##### 採点の固定基準（案）

| 観点 | 配点 | 見るところ |
|---|---|---|
| 構成 | 30 | topic sentence で意見がはっきり述べられているか、理由と例がそろっているか、concluding sentence で締めているか |
| 内容 | 25 | 理由が意見を支えているか、例が具体的か、話がそれていないか |
| 文法 | 20 | 時制・主語と動詞の一致・冠詞・文の形 |
| 語彙・表現 | 15 | 語の選び方、transition words の使い方、言い回しの自然さ |
| 課題の条件 | 10 | 語数・文数の指定、構成や表現の条件を満たしているか |

##### 画面構成

- **一覧画面**: パラグラフの一覧と「新規作成」。ヘッダから学習ガイドへ移れる（後で振り返りも）
- **編集画面**: 3 ペイン
  - 左: 段階の切り替え（課題 / アイデア / アウトライン / 下書き）
  - 中央: 選んだ段階の編集欄。下書きの段階では、アウトラインを中央の上半分か左右に並べて表示する
  - 右: AI のペイン（アイデア出しの候補、採点結果と指摘）。タブで学習ガイドに切り替えられる
- **学習ガイド画面**: 構成の解説 / モデル文 / 表現集のタブ。編集画面の右ペインでも同じ中身を開ける

##### Dropbox 上のデータ配置（案）

パラグラフごとにフォルダを 1 つ作り、段階ごとにファイルを分ける。

```
/akira/Documents/esl-writing/            ← 専用フォルダ（名前は Phase 3 で確定）
  paragraphs/
    2026-11-08-school-uniforms/          ← 作成日 + テーマから作るフォルダ名
      assignment.md                      ← テーマ・課題の条件
      ideas.txt                          ← アイデアのメモ
      outline.txt                        ← アウトライン（字下げテキスト。daily-note のマップと同じ形式）
      draft.txt                          ← 下書きの本文
      feedback.json                      ← 最新の採点結果（点数・内訳・指摘）。採点のたびに上書き
```

ファイルを分ける理由:

- 段階ごとに別々に自動保存でき、`rev` による競合の判定もファイル単位で済む（メモを書いているときに下書きと競合しない）
- `outline.txt` と `draft.txt` はただのテキストなので、Dropbox で直接開いても読める。アウトラインは daily-note のマップでも開ける
- `feedback.json` は機械が読み書きするデータなので JSON にし、振り返り機能で全パラグラフを横断して集めやすくする

学習ガイドの中身（解説・モデル文・表現集）はパラグラフごとに変わらない固定コンテンツなので、Dropbox ではなくリポジトリに置く。

##### Phase 3 で決めること

- 専用フォルダの名前（案: `/akira/Documents/esl-writing/`）
- `.docx` / PDF に入れる見出し（名前・クラス名・日付・テーマなど）と体裁
- モデル文の作り方（AI に作らせて人が確認する、授業の教材をもとにする、など）

#### Phase 3 の決定（2026-11-08）

上の機能案に、次の変更を加えて確定した。確定版は `CLAUDE.md` の「アプリの内容」。

- 専用フォルダは **`/akira/Documents/esl-writing/`**
- 書き出しは、まず**プレーンテキストだけ**にする。`.docx` / PDF と体裁は後で足す
- **最初は AI の機能を極力入れない**。AI のアイデア出しと、AI の採点と指摘は後回しにし、後から足していく。`feedback.json` も AI の採点を作るときに足す
- 実装の前に**デザイン例をいくつか作り**、その中から選んでから実装する
- モデル文の作り方は、学習ガイドを作るときに決める
