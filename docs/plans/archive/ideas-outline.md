# アイデアの段階をなくし、最初からアウトラインを作る（AI なし）

## 目的・背景

今の STEP 2 アイデア（`ideas.txt` の自由テキスト）と STEP 3 アウトライン（`outline.txt` のマインドマップ）には繋がりが何もない（2026-11-09 の指摘）。

- STEP 3 の画面にメモが出ないので、行き来しながら手でマップへ打ち直すしかない
- AI の理由・例の候補もメモへ書き足すだけで、マップへは届かない

最初は「置き場とマップを並べ、アイデアを置き場からマップへ移す」案を考えたが、2 か所を行き来する仕組みは上手くいかないと判断した（2026-11-09）。
**最終の目的はアウトラインを作ること**なので、アイデアの段階をなくし、**最初からアウトライン（マップ）の上でアイデアを出す**ようにする。

アイデアを出す手助けは、別の欄ではなくマップの上で行う:
- 選んでいる項目に合わせて「次に何を考えるか」の問いを出す（AI なし）
- 足りないところは今ある型のチェック（✓ / !）で分かる

**このプランは AI なしでアウトラインを埋めていくところまで**（2026-11-09 決定）。AI をマップに繋ぐのは後で別のタスクにする（「後でやること」の節）。

## 対応方針

### 1. 段階は 3 つにする

| 段階 | やること | 言語 |
|---|---|---|
| 1. 課題 | 今のまま | 条件は日本語でも可 |
| 2. アウトライン | マップの上でアイデアを出しながら骨組みを作る | 日本語可 |
| 3. 下書き・推敲 | 今のまま | 英語のみ |

- `STAGES` から `ideas` を外す（`assignment` / `outline` / `draft`）。保存層・API・一覧の進み具合・タイル・次のステップのボタンは `STAGES` に従って 3 つになる
- 旧 URL の `#/p/<id>/ideas` は `outline` として開く（`route.ts`）
- **`ideas.txt` はアプリから読まなくなる**。Dropbox のファイルは消さずに残す（必要なら Dropbox で開ける）。一覧の「更新日」・進み具合にも数えない
- 消すもの: `src/browser/views/ideas.ts`、`shared/ideas.ts` の `appendToMemo`・`memoBlock`、タイルの「N 行」

### 2. マップの上でアイデアを出す（AI なし）

マップの上に、**選んでいる項目の役割に合わせた問い**を 1 行で出す（役割は `outline-roles.ts` の深さ → 役割と同じ）。

| 選んでいるもの | 出す問い（例） |
|---|---|
| 空のマップ | テーマへの答え（賛成か反対か）を中心に書く |
| 中心（意見） | なぜそう思う？ 理由を子に足す（Tab） |
| 理由 | たとえば？ 体験・数字・場面を子に足す |
| 例 | もっと具体的に言える？（いつ・どこで・いくら） |
| 結論 | 意見を別の言い方で言い直す。新しい理由は足さない |

- 今の型のチェック（意見 1 つ／理由 2〜3 つ／どの理由にも例／結論）はそのまま。問いは「次に何を書くか」、チェックは「全体で足りないもの」と役目を分ける
- 中心が空のときのマップの仮の名前は今のまま（テーマ → 無ければ「意見」）

### 3. 今ある AI の扱い

- 右ペインの「AI案」の**理由・例の候補**は、書き足す先のメモが無くなるので「メモに足す」ボタンを外し、**見るだけ**にする（見ながら自分でマップに足す）
- テーマの候補・アウトラインを見てもらうは今のまま
- プロンプトは変えない（本物の API での確認は要らない）

## 影響範囲

- `src/shared/types.ts`（`STAGES`・`STAGE_FILES`）、`route.ts`（旧 URL）、`stage-summary.ts`、`src/browser/ui.ts`（段階の名前）
- `src/paragraphs/store.ts`（`ideas.txt` を数えない）、`src/scripts/dropbox-check.ts`・`dropbox-smoke.ts`
- `src/browser/views/edit.ts`（3 つのタイル、メモへの書き足しを外す）、`views/outline.ts`（問いの行）、`views/ideas.ts`（消す）、`views/list.ts`
- `src/browser/map.ts`（選んでいる項目を外へ知らせる）
- 新しい純関数: 役割 → 問い
- `src/browser/ideas-pane.ts`（理由・例の候補を見るだけに）
- `web/style.css`、`CLAUDE.md`（書く流れの表・MVP・画面構成・ファイルの配置・データ保存）
- 決定版のモック（`docs/plans/archive/design-examples/decided.html`）は経緯として残し、直さない

## テスト方針

- 段階: `STAGES` が 3 つ、旧 URL `ideas` → `outline`、一覧の進み具合と更新日に `ideas.txt` を数えない
- 役割 → 問い: 空・中心・理由・例・結論・字下げ 0 が複数のときに出す問い
- `memoBlock`・`appendToMemo` のテストは消す
- 画面はブラウザで一通り触って確かめる（3 つのタイル・旧 URL・問いが選択に合わせて変わる・空のマップから埋めていける・理由・例の候補にボタンが無い）

## Phase

- **Phase 1: 段階を 3 つにする** — `ideas` を外す・旧 URL・一覧とタイル・`ideas.txt` を数えない・`CLAUDE.md`
- **Phase 2: マップの上の問い** — 選んでいる項目の役割に合わせた問いの行
- **Phase 3: 後片付け** — `DONE.md`・プランを archive へ

## 後でやること（このプランではやらない）

`TODO.md` の「後で」に入れる。やるときに別のプランを作る。

- **AI の理由・例の候補をマップに直接足す**: 「マップに足す」で理由を中心の子、例をその子として入れる。結論（中心の最後の子が「結論」で始まるもの）があればその前に入れる（後ろだと結論と判定されなくなる）。マップが空ならその立場の意見を中心にしてから入れる。マップの操作の 1 手として Ctrl+Z で戻せるようにする（`map.ts` に外からの変更を履歴に積む入口を足す）。プロンプトの「メモ」の言い方を直し、本物の API で確かめる
- **掘り下げの問い**（作るか決める）: マップで選んでいる項目について、考えを引き出す問いを AI が日本語で 2〜3 つ出す。答えや足すべき文は出さない
