# 下書きエディタ

## 目的・背景

編集画面の STEP 4（下書き・推敲）を作る。英語で本文を書き、課題の指定に対して語数・文数が足りているかを常に見られるようにし、
アウトラインを構成の役割の色で並べたリストを横に見ながら書けるようにする（`CLAUDE.md` の「最初に作るもの」「画面構成」、モックは `decided.html` の編集画面）。

## 決定（2026-11-08）

- **深さ → 役割**: 中心 = Topic sentence（青）、子 = Reason（緑）、孫より深いもの = Example（橙）
- **結論（紫）の見分け方は案 A**: 中心の子のうち**最後のもの**の名前が「結論」「まとめ」「Conclusion」で始まっていれば結論（その子孫も結論）。それ以外は理由
- **型から外れたとき**: 字下げ 0 の行が 2 つ以上なら、それぞれを Topic sentence として並べる（警告は出さない）。結論の見分けはそれぞれの最後の子と、字下げ 0 の最後の行に同じ規則を当てる

## 対応方針

### Phase 1: 数え方とメーター・役割の純関数（`src/shared/`）

- `counting.ts`: 語数と文数
  - 語: 英字・数字のひと続き（`don't`・`well-known`・`3.5` は 1 語）。骨組みで仮に入れた `countWords` をここへ移して正式にする
  - 文: `.`・`!`・`?`（続く引用符・括弧も含む）のあとに空白か本文の終わりが来たら文の終わり。
    `Mr.`・`Dr.` などの敬称は終わりにしない。`etc.`・`e.g.`・`a.m.` などは、次が大文字か本文の終わりのときだけ終わりにする。
    小数（`3.5`）は終わりにしない。最後に句点の無い文があれば 1 文と数える
  - 日本語（ひらがな・カタカナ・漢字）が混じっているか（下書きは英語のみなので知らせる）
- `meter.ts`: 数と指定の幅から、メーターの状態（足りない・範囲内・多い・指定なし）・文言（「あと 52 語」「範囲内」「12 語多い」）・帯と目盛りの位置を出す。
  目盛りの最大は指定の上限（無ければ下限）の 1.2 倍と今の数の大きい方（モックと同じ）
- `outline-roles.ts`: アウトラインのテキスト → 役割つきの並び（上の決定どおり）。理由には番号（REASON 1…）
- 段階のタイルのアウトラインの行を「理由 3」に差し替える（理由が無ければ今までどおり「N 項目」）

### Phase 2: 下書きの画面

- 上: 語数・文数のメーター 2 つ（モックの `.meters`）と課題の帯（`brief.ts`）。日本語が混じっていれば注意を 1 行
- 下: 本文の欄（Georgia・17px・行間広め。`lang="en"`）と、右にアウトラインのリスト（250px。役割の色・見るだけ。アウトラインが空なら STEP 3 へのリンク）
- 打つたびにメーターと注意を更新し、`editor.update(text)`
