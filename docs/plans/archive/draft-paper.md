# 下書きの本文の欄を画面の下いっぱいに広げ、ノートの罫線を引く

## 目的・背景

STEP 3（下書き・推敲）の本文の欄（`.paper` の textarea）について、2026-11-11 にユーザーから 2 つの要望があった。

1. **画面の下いっぱいまで広げる**: 今は本文の欄の下に「書き出し →」のボタンと中央のペインの下の余白（4rem）があり、
   1440×900 の画面では下の約 125px が使われていない（本文の欄は y = 215〜775px、ボタンは 795〜835px）
2. **daily-note と同じく、紙のノートのような下線（横罫）を出す**

見え方だけの変更で、本文・保存・数え方・書き出しには触れない。

## 今の作り

- 中央のペイン `.center` は `padding: 1rem 1.2rem 4rem`。中身は見出し・`.stage-body`（`flex: 1 0 auto`）・次のステップへのボタン `.stage-next`
- 下書きの画面（`src/browser/views/draft.ts`）は `.draft`（縦の flex）に、メーター・日本語の注意・課題の帯・`.work`（本文の欄 `.paper` と、右にアウトラインのリスト `.struct` の 2 列のグリッド。`flex: 1; min-height: 360px`）
- `.paper` は Georgia 17px・`line-height: 1.95`（= 33.15px と端数）・`padding: 1.1rem 1.3rem`、角丸 14px と影
- アウトラインの画面だけは `.stage-body.fill`（`flex: 1 1 0; min-height: 480px`）で高さを決めて、中身を枠の中でスクロールさせている

## daily-note の罫線の作り（`~/daily-note/src/web/html.ts`。経緯は daily-note の `docs/plans/archive/editor-ruled-lines.md`・`ruled-lines-alignment.md`）

- 要素を重ねず、**textarea の背景**に `repeating-linear-gradient` で横罫を敷く（本文・選択・IME・折り返しに触らない）
- 罫線の間隔は 1 行の高さそのもの（`--note-row`）。**行の高さを `round()` で整数 px にそろえ、本文の `line-height` にも同じ値を使う**
  （端数のままだと、ブラウザが行の箱を整数に丸めるのに罫線は端数で進み、行ごとにずれる）
- `background-attachment: local`（本文と一緒にスクロールさせる）・`background-origin: content-box`（1 行目の頭から数える）・
  `background-repeat: no-repeat` と高さの指定（上と左右の余白には引かない）・`background-clip: padding-box`（下の余白には引く）
- 下に数行ぶんの余白（`--note-tail`。行の高さの倍数なので、余白の罫線も本文の続きに乗る）
- Firefox は textarea の背景に `local` を効かせないので、Firefox だけ JS がスクロールの量と本文の高さを CSS 変数で渡して背景を動かす

## 対応方針

### 1. 本文の欄を画面の下いっぱいに広げる

- 下書きの画面も、アウトラインと同じく `.stage-body` の高さを中央のペインに合わせる（中身を伸ばさず、本文の欄の中でスクロールさせる）
- 中央のペインの下の余白（4rem）は下書きの画面だけ詰め、本文の欄の下端を中央のペインの下端の少し上（1rem ほど。カードの角と影を残す）に置く
- 窓が低いときは今どおり本文の欄の最低の高さ（360px）を守り、足りなければ中央のペインがスクロールする
- 「書き出し →」のボタンは本文の欄の下から動かす（置き場所は「決めること」）。STEP 1・2 の次のステップへのボタンは今のまま
- 右のアウトラインのリストは今どおり本文の欄と同じ高さ（長ければ中でスクロール）

### 2. ノートの罫線

- daily-note と同じ作りにする: `.paper` の背景に横罫を 1 枚敷く。行の高さは CSS 変数（例 `--paper-row: round(17px * 1.95, 1px)` = 33px）にして、`line-height` も同じ値にする
- 罫線の色は紙の色に合う薄い色（例 `#e6dfcf`。既存の `--line` 系の近く）。CSS 変数にして 1 か所で変えられるようにする
- 下に 3 行ぶんの余白（行の高さの倍数）。最後の行を書いていても下が見え、余白にも罫線が続く
- 1 行目の上（上の余白）と左右の余白には引かない。プレースホルダー（「In my opinion, …」）も 1 行目の罫線の上に乗る
- Firefox: daily-note と同じく、Firefox だけ JS（`draft.ts`）がスクロールの量と本文の高さを `--rule-scroll`・`--rule-h` で渡し、`@supports (-moz-appearance: none)` の CSS が背景を動かす
- 印刷（提出用の PDF。`#print-sheet`）と書き出しは別の要素なので罫線は出ない（変えない）

## 進め方（Step）

### Step 1: 本文の欄を下いっぱいに広げる・「書き出し →」を動かす

- `views/edit.ts`: 下書きのときも `.stage-body` に高さを決めるクラスを付ける（アウトラインの `fill` と同じ考え方）。下書きのときは次のステップへのボタンを `.stage-next` に出さず、決めた場所に置く
- `views/draft.ts`: 決めた場所に「書き出し →」を置く（押したときの動きは今の `openExport` を受け取って使う）
- `style.css`: 下書きの画面の高さの決め方・中央のペインの下の余白・`.work` と `.paper` の高さ

### Step 2: 罫線

- `style.css`: `.paper` に `--paper-row`・罫線の色・背景の横罫・下の余白（daily-note の決まりどおり）
- 行の高さが整数になることと、罫線が各行の下端に乗ることを、Chromium で測って確かめる（daily-note の測り方: 文字の位置とすぐ下の罫線の距離が、先頭と末尾までスクロールしたときで変わらない）

### Step 3: Firefox で罫線をスクロールに追従させる

- `views/draft.ts`: 本文の欄の `scroll` と大きさの変化で `--rule-scroll`・`--rule-h` を入れる（`ResizeObserver`。段階を移るときに外す）
- `style.css`: `@supports (-moz-appearance: none)` で背景の位置と高さをその値から決める
- Playwright の Firefox で確かめる（入っていなければ入れてから。入れられなければ、このプランに書いて Chromium だけ確かめる）

### Step 4: 後片付け

- `CLAUDE.md` の「画面構成」（下書きの本文の欄・罫線）と、次のステップへのボタンの書き方（STEP 3 の「書き出し →」の場所）を直す
- このプランを `docs/plans/archive/` へ、`TODO.md` の項目を `DONE.md` へ

## 影響範囲

- `src/browser/views/draft.ts`（「書き出し →」の置き場所・Firefox の罫線）
- `src/browser/views/edit.ts`（下書きのときの `.stage-body` のクラスと次のステップへのボタン）
- `web/style.css`（`.center` の下の余白・`.stage-body`・`.work`・`.paper`・罫線）
- サーバ・API・DB・数え方・書き出しの中身は変えない

### 変えてはいけない動き

- 表現集から本文への挿入（カーソルの位置に入る・Ctrl+Z で戻せる。`phrase-target.ts`）
- 自動保存・語数と文数のメーター・日本語の注意
- 右のアウトラインのリストは本文の欄と同じ高さで、長ければ中でスクロールする（中身の長さで欄ごと伸びない）
- 学習ガイドの引き出しと右ペインの幅のドラッグ（本文の欄の幅が変わっても罫線は崩れない）

## テスト方針

- DOM を使わない部分は増えない見込み（純関数を足したらテストする）。既存の `npm test`・`npm run typecheck`・`npm run lint` が通ること
- 画面: 作業用の DB・3017 番のサーバ（`.env` を読まないので Dropbox のバックアップは動かない）で、Playwright（Chromium）で確かめる
  - 1440×900 と 1280×800 で、本文の欄の下端が中央のペインの下端の近くにあること・「書き出し →」が決めた場所で押せること
  - 窓を低く（例 1440×640）したとき、本文の欄が 360px を下回らず中央のペインがスクロールすること
  - 罫線: 長い本文を入れて、先頭と末尾までスクロールしたときで、文字と罫線の距離が変わらないこと。右ペインの幅を変えても崩れないこと
  - 表現集から入れる・保存されることを 1 回
- Firefox（Step 3）は Playwright の Firefox で同じ罫線の確かめ方
