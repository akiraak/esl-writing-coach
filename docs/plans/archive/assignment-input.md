# 課題の入力（と自動保存の共通の仕組み）

## 目的・背景

編集画面の STEP 1（課題）を作る。テーマ・語数の指定・文数の指定・構成や表現の条件を入力し、`assignment.md` に保存する。
ここで決める書式は、一覧（テーマ）・下書き（語数・文数のメーター、条件の表示）から読まれる。

課題は最初に保存が要る画面なので、**段階のファイルを自動保存する共通の仕組み**もこのタスクで作る
（2026-11-08 の決定。TODO では「編集画面の骨組み」に入っていたものを移す）。

## 決定（2026-11-08、ユーザーが案のまま了承）

1. `assignment.md` の書式は下の案のとおり
2. 語数・文数の指定は「下限〜上限（片方だけも可）」。「約 150 語」は自分で `140-160` などの幅に直して入れる
3. 一覧の「新規作成」ではテーマを聞き、その場で `assignment.md` にテーマを書いてから課題の画面を開く（画面は「一覧画面」のタスク。API はこのタスクで対応する）
4. 自動保存の共通の仕組みはこのタスクで作る

## 対応方針

### Phase 1: `assignment.md` の書式（`src/shared/assignment.ts`。純関数）

```markdown
# Should students wear school uniforms?

- 語数: 120-150
- 文数: 8-10

## 条件

理由を 3 つ挙げ、First / Second / Finally を使う。
結論で topic sentence を別の言葉で言い換える。
```

- 型: `{ theme, words: { min, max }, sentences: { min, max }, conditions }`（`min` / `max` は数か null）
- 読み取り: 最初の `# ` 行がテーマ、`- 語数:`・`- 文数:` の行が指定、`## 条件` から下が条件
- 指定の書き方: `120-150`・`120-`（以上）・`-150`（以下）・`120`（ちょうど）・空（指定なし）。全角の数字や `〜`・`~`・`–` も読む
- **手で書き換えて形が崩れても内容を消さない**: 読み取れなかった行は条件の先頭に回す（保存し直しても失われない）
- 書き出しは常に上の形。読み → 書き → 読みで同じ値に戻る

### Phase 2: 自動保存の共通の仕組み

- 状態の移り変わりは `src/shared/autosave.ts`（タイマーと保存の関数を差し込める。node でテストする）
  - 打ち終わって **3 秒**で保存する。保存中に打てば、保存が終わってからもう一度保存する
  - 保存できたら新しい `rev` を持ち、次の保存に使う
  - **競合（409）を 1 度でも見たら自動保存を止める**。手元の内容は消さず、知らせるだけ（daily-note と同じ。黙って再送しない）
  - 通信・Dropbox の失敗は「保存できません」を出し、次に打ったとき・「再試行」で保存し直す
  - 画面を離れるとき（段階・画面の切り替え）は、待たずにその場で保存する。タブを閉じるときに未保存があれば確認を出す
- 画面側（`src/browser/save-status.ts`）: ヘッダに「保存済み 14:32 / 保存中… / 未保存 / 保存できません」、競合のときは本文の上に知らせ
  （「他で更新されています。自動保存を止めました」+「読み直す（手元の変更は捨てる）」）

### Phase 3: 課題の画面

- 中央のペイン: テーマ（大きめのセリフ体の 1 行）、語数・文数（下限〜上限の数字の欄）、条件（複数行）
- 打つたびに `assignment.md` の本文を組み直して自動保存に渡す
- 下限が上限より大きいときは注意を出す（保存は止めない）
- ヘッダのパンくずはテーマを出す（どの段階でも。テーマが空なら id）
- 段階のタイルの「日本語可」の印が折り返す件を直す

### Phase 4: 新規作成でテーマを書く（API）

- `POST /api/paragraphs { theme }` は、フォルダを作ったあと、テーマだけを入れた `assignment.md` を保存する

## 結果（2026-11-08）

- 4 Phase とも完了。`npm test` 118 件・lint・型チェック（ブラウザ向けを含む）が通る
- 作業用の保存先（`.ui-test/`）を向けた別ポートのサーバとヘッドレスの Chromium で、本物の Dropbox を相手に確かめた（最後に `.ui-test/` は消した）:
  新規作成でテーマが入る / 入力して 3 秒で「✓ 保存済み」/ 読み直しても残る / 下限 > 上限の注意 / パンくずがテーマに追従 /
  課題 → アイデア → 課題と素早く移っても誤った競合にならない / 別の端末を装って先に保存すると「自動保存を停止」と知らせが出て、Dropbox の内容は上書きされない
- 確認の途中で見つけて直したもの:
  - 段階を素早く行き来すると、前の画面の保存が終わる前に読み直して古い rev で編集が始まり、次の保存が誤って競合になった。
    待つ相手を「1 つ前の画面」ではなく「まだ終わっていない保存の全部」にした（`src/browser/main.ts`）
  - ヘッダの保存の状態と競合の知らせが同じクラス名（`conflict`）で、ヘッダが枠つきに見えた。知らせを `conflict-banner` にした

## テスト方針

- `assignment.ts`: 読み取り（正しい形・崩れた形・全角）、書き出し、往復
- `autosave.ts`: 偽のタイマーと保存の関数で、3 秒待つ・続けて打てば延びる・保存中の入力・rev の引き継ぎ・競合で止まる・失敗からの再試行・離れるときの即保存
- API: 新規作成でテーマ入りの `assignment.md` が保存される
- 本物の確認: 作業用の保存先（`DROPBOX_ROOT=<保存先>/.ui-test`）で別ポートのサーバを立て、ヘッドレスのブラウザで入力 → 自動保存 →
  読み直して残っていることを確かめ、最後に作業用フォルダを消す（本物の `paragraphs/` には触れない）
