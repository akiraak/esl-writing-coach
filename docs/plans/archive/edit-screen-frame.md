# 編集画面の骨組み

## 目的・背景

編集画面（3 ペイン）の骨組みを仕上げる。いまは段階を切り替えるたびに画面ごと作り直し、ファイルを読み直している。
`CLAUDE.md` の「段階の切り替えはページ遷移なしで行う。4 つのファイルの `rev` と未保存の状態はブラウザ側で持ち、ファイルごとに自動保存する」に合わせる。
あわせて、モック（`docs/plans/archive/design-examples/decided.html`）にある段階のタイルの状態の行と、右ペインの切り替えを入れる。

各段階の中身（アイデア・アウトライン・下書き）と学習ガイドの中身はそれぞれのタスクで作る。ここでは入れ物だけ。

## 対応方針

### Phase 1: パラグラフを開いている間、4 つの段階をまとめて持つ

- 編集画面を開いたら 4 つの段階のファイルを並べて読み、段階ごとに自動保存（`StageEditor`）を 1 つずつ作って、**パラグラフを開いている間は持ち続ける**
- 同じパラグラフの中で段階を移るときは、ヘッダ・タイル・右ペインはそのまま、中央だけを描き直す（読み直さない）
  - 離れる段階は待たずに保存する（`flush`）。持ち続けるので rev は保存が終わったときに手元で新しくなり、古い rev で編集を始めることはない
- 一覧・学習ガイド・別のパラグラフへ移るときは、全部の段階を保存してから閉じる（いまと同じく、次の画面は保存を待ってから読む）
- 画面の入口（`src/browser/main.ts`）: `View` に「この画面のまま移れるか」（`navigate(route)`）を足し、移れるなら作り直さない
- 競合の「読み直す」は、その段階のファイルだけを読み直す（いまは画面ごと作り直している）

### Phase 2: 段階のタイルの状態と、ヘッダの保存の状態

- タイルに状態の行（モックの `120–150 語`・`7 行` など）を出し、打つたびに更新する。純関数 `src/shared/stage-summary.ts`
  - 課題: 語数の指定（無ければ文数の指定、どちらも無ければ「指定なし」）
  - アイデア: 空でない行の数（`7 行`）
  - アウトライン: 空でない行の数（`5 項目`）。「理由 3」のような役割ごとの数は、深さ → 役割の規則を決める下書きのタスクで差し替える
  - 下書き: 語数（`68 語`）。数え方は仮（英数字の並び。`don't`・`well-known` は 1 語）で、下書きのタスクで詰める
  - どれも空なら「未着手」
- タイルに保存の印: 未保存・保存中は点、保存できないときは赤い点、競合は「競合」
- ヘッダの保存の状態は 4 つの段階をまとめて 1 つ出す（競合 > 保存できません > 保存中 > 未保存 > 保存済み）。まとめ方は純関数（`combineSaveStates`）。「再試行」は保存できなかった段階を全部やり直す
- 競合の知らせは、その段階を開いているときに中央の上に出す

### Phase 3: 右ペインとスクロール

- 右ペインの「構成 / モデル文 / 表現集」を押して切り替えられるようにする（中身は学習ガイドのタスクで入れる。いまは仮の文）。`src/browser/guide-pane.ts` に分け、学習ガイドのタスクではここに中身を入れる
- 選んだタブは段階を移っても保つ
- 画面の高さに収め、左・中央・右のペインがそれぞれスクロールする（モックと同じ）

## 影響範囲

- `src/browser/main.ts`・`src/browser/view.ts`・`src/browser/views/edit.ts`・`src/browser/stage-editor.ts`
- 新規: `src/shared/stage-summary.ts`・`src/browser/guide-pane.ts`
- `src/shared/autosave.ts`（`combineSaveStates` を足す）・`web/style.css`

## テスト方針

- `test/stage-summary.test.ts`: 段階ごとの要約・語数の仮の数え方
- `test/autosave.test.ts`: `combineSaveStates` の優先順位と保存済みの時刻
- 画面は 3017 番で立て、ヘッドレスブラウザで確かめる（試し用のパラグラフを作り、最後に消す）
  - 段階を移っても読み直しが起きない（`GET .../stages/` の回数）・打った内容が段階を移って戻っても残る・保存される
  - 一覧へ戻ると保存が終わってから読む
