各モックは単体で開ける静的 HTML。画面下（案 D は右下）の切り替えで **一覧 / 編集（下書き）/ 学習ガイド** を行き来できる。

中身はすべて架空のサンプル（テーマ「Should students wear school uniforms?」、本文 68 語・6 文、課題の指定 120–150 語・8–10 文）。
外部リソース（Web フォント・CDN）は読まない。PC 専用なので横幅 1200px 以上を前提にし、狭い画面は考えていない。

## 選ぶときの論点

1. **下書きの横にアウトラインをどう見せるか**（一番効く）
   - 図（A）は、アウトライン段階と同じ見た目で骨組みが一目で分かる。代わりに縦に場所を取り、本文が下へ押される
   - テキスト（B / D）は場所を取らず、本文と並べて長く書ける。図ほど構造は目立たない
   - 色つきリスト（C）は、「どの行が理由でどの行が例か」が色で分かる。モデル文の色分けとも対応する
2. **明るさ**: ライト（A / C / D）か、ダーク（B）か
3. **右ペインを閉じられるか**: 学習ガイドを常に出す（A / B / C）か、閉じて本文を広げられる（D）か
4. **一覧に何を出すか**: テーマと更新日だけ（A / D）、フォルダ名と時刻も（B）、4 段階の進み具合も（C）

案を組み合わせてもよい（例: 「A の見た目 + D の閉じられる右ペイン」「C の色 + B のステータス行」）。

## 実装するときに効いてくる制約

- **一覧に語数は出さない。** 出すには全パラグラフの `draft.txt` の `download` が要る。一覧は `list_folder` のメタデータ（パス・サイズ・更新日時）だけで描く
- **C の進み具合は、ファイルのサイズで判定する**（無い・0 バイト = 未着手）。そのため新規作成のときに空のファイルを作るかどうかを決めておく必要がある
- **C の色分けには「深さ → 役割」の約束が要る**: 深さ 0 = 意見、深さ 1 = 理由、深さ 2 以降 = 例・詳細。結論は「`結論:` で始まる深さ 1 の行」とするなど、規則を決める
- **A のマップは読み取り専用で描く。** daily-note の `map.ts` は編集の操作を持っているので、それを止めて描くだけの使い方を足す
- **D の右ペインの開閉状態**は、端末ごとの見た目の設定なので Dropbox には置かない（localStorage でよい）
- 本文の字は英語向けにセリフ体（Georgia）、画面の文字は system-ui にしている。どの案でも外部フォントは読まない

## 決定: **構成は案 C、色合いは案 A** — 2026-11-08

決定版のモック: **`decided.html`**（案 C の HTML に案 A の色を当てたもの）。

- **構成は案 C（ワークブック）**: 左 = 段階のタイル（「日本語可 / 英語のみ」の印つき）、中央 = 語数・文数のメーター + 課題の条件 + 本文 + 役割の色つきアウトライン、右 = 学習ガイド（常に表示）、一覧 = カード + 4 段階の進み具合
- **色合いは案 A（ノート）**: 暖色の紙（背景 `#f6f3ec`・カード `#fffdf8`・文字 `#2a2620`）と深緑の差し色（`#2f6f62`）。英文の本文とテーマの見出しは Georgia
  - 構成の 4 役割の色は紙に合わせて彩度を落とした: Topic sentence `#3b6ea5` / Reason `#4a8a55` / Example `#c07a2c` / Concluding sentence `#82589e`（背景はそれぞれ薄い色）
- **マインドマップは「3. アウトライン」の編集でだけ使う。** 下書きの横には図を出さず、案 C の色つきリスト（見るだけ）を出す。
  そのため案 A で必要だった「マップの読み取り専用表示」は作らない
