# AI のアイデア出し

## 目的・背景

「後で足すもの」の 1 つ。テーマを決めるとき（STEP 1）と、理由・例を考えるとき（STEP 2）に、AI に候補を出させる。
2026-11-08、次の作業として Claude が選んだ（採点の AI の土台をそのまま使える・書き始めのつまずきに効く）。

決まっていること（CLAUDE.md・`docs/plans/archive/app-features.md`）:
- テーマ候補と、理由・例の候補を**ボタンで**出す（自動では走らせない）
- 出た候補は**メモに書き足せる**（自動では書き込まない。押したときだけ）
- 右ペインに出す（「AI のペイン（アイデア出しの候補、採点結果と指摘）」）

## この作業で決めること（指定が無いので既定で進め、見直せるようにする）

- **場所**: 編集画面の右ペインに「AI 案」タブを足す（構成 / モデル文 / 表現集 / 採点 / AI 案）
- **テーマの候補**: 分野やキーワード（任意。日本語でよい）を入れて「テーマの候補を出す」→ opinion paragraph 向けの問い（英語）5 つと日本語訳。
  各候補に「課題のテーマにする」（押したときだけ課題のテーマを書き換える）
- **理由・例の候補**: 課題のテーマ（手元の最新）で「理由・例の候補を出す」→ 賛成側・反対側それぞれ理由 3 つ、各理由に例 1〜2 つ。**日本語**で出す
  （メモは日本語可。英文は自分で書くので、英語の文は出さない）。各理由に「メモに足す」（理由と例をアイデアのメモの末尾に書き足す）
- **保存しない**: 候補は画面の中だけ（編集画面を開いている間）。ファイルには書かない
- **モデル**: 採点と同じ `claude-opus-5-5`（`fallbacks: "default"` も同じ）。effort は `medium`（候補出しは採点ほどの正確さが要らず、速さを取る）
- **送るもの**: テーマの候補は入れた分野・キーワードだけ。理由・例の候補は課題のテーマと条件だけ（下書き・メモは送らない）

## 対応方針

### Phase 1: プロンプト・出力のスキーマと検証（純関数。`src/ai/ideas.ts`）・メモへの書き足しの整形（`src/shared/ideas.ts`）
### Phase 2: サーバ（`POST /api/ai/themes`・`POST /api/ai/ideas`。SDK の呼び出しは採点と共通にする）
### Phase 3: 画面（右ペインの「AI 案」タブ）
### Phase 4: 本物の API で確かめる（ユーザーの了承が要る）
